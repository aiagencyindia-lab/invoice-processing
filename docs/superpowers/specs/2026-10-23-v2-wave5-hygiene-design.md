# Wave 5 — `agent_actions` retention and OCR for injection scanning (`v2/w5-hygiene`, branch D)

**Program plan:** `docs/superpowers/plans/2026-10-23-v2-wave5-program.md` (B7, B8). **Owns:** `worker/runner.py` (one sweep), `trust/agents/inputs.py`, `trust/agents/later.py` (one keyword), `confidence.py` (`ocr_page_text` bytes path), `tests/test_trust_agents_retention.py`, `tests/test_trust_agents_inputs.py`. **Touches nothing else**; `AgentStore.purge_before` and the `agents.retention_days` threshold come from the scaffold.

## Retention sweep (B7)

- `worker/runner.py`: `RETENTION_SCAN_SECONDS = 86_400`; `Worker._last_retention_scan = None`; `_purge_agent_actions_if_due()` called from `run_forever` after `_deliver_webhooks_if_due()` (so the first pass runs on the first loop, then daily). Same shape as the two existing sweeps: `try … except Exception: logger.exception("Agent-action retention sweep failed; continuing.")`.
- Per active tenant, inline in `_purge_agent_actions_if_due`: `select(Tenant.id).where(Tenant.status == "active")` in a plain `Session(get_engine(url))` (as `trust/webhooks/deliver.py` and `trust/apikeys.py` do; `tenants` has no RLS), then per tenant (`purge_before` opens its own `tenant_session`): `settings = thresholds.merged(tenant_settings.effective(tenant_id).get("trust_thresholds"))`; `days = max(_days(settings["agents.retention_days"], 400), _days(settings["agents.split_window_days"], 7) + 1, 31)` where `_days(v, default)` is `int(float(v))` for a finite non-negative number, else `default` (a bad tenant value never purges more, never raises); `n = store.purge_before(tenant_id, now − days)`; one `logger.info("agent_actions_purged", extra={"rows": n})` per tenant with rows > 0 (no tenant id in `extra`). One tenant's failure is logged and the loop continues.
- `purge_before` already keeps every `vendor.create` row (`creators_of` is unbounded: the circular and unverified-vendor rules depend on them). The floor keeps every cap period (calendar month) and split window inside the retained range. A finding's `details.action_id` may then point at a purged row; the finding carries its own copy of the reasons, and the ledger routes answer with what remains.
- No store or table change; `agents.retention_days` is a per-tenant threshold like the others (`PUT /api/trust/thresholds` path already exists for admins).

## OCR fallback for the injection scan (B8)

- `confidence.ocr_page_text(pdf: Path | bytes, *, max_pages: int | None = None) -> list[str]`: `pypdfium2.PdfDocument` accepts bytes as well as a path, so the body changes only in what it hands to `PdfDocument` and in stopping after `max_pages`. Behaviour for the existing callers is unchanged (they pass a `Path`, no cap).
- Budget: `ocr_page_text(..., deadline: float | None = None)` stops rendering further pages once `time.monotonic()` passes `deadline`; `text_of` passes `now + OCR_BUDGET_SECONDS` with `OCR_BUDGET_SECONDS = 120`, well inside the queue's 600 s ack deadline (`worker/queue.py DEFAULT_ACK_DEADLINE_SECONDS`), so a slow scan never outlives its lease and is never redelivered mid-OCR (my call).
- `trust/agents/inputs.py`: `MAX_OCR_PAGES = 5`; `text_of(document, blobs, *, ocr: bool = False)`: after the text layer is read, when `ocr` is true and `confidence.has_readable_text([layer])` is false, append `"\n".join(confidence.ocr_page_text(blob_bytes, max_pages=MAX_OCR_PAGES, deadline=…))` under the same `_read` guard. The blob is fetched once into a local and fed to both `page_text` and OCR. OCR runs only on bytes `page_text` itself would read (`%PDF` prefix, ≤ `pdfmeta.MAX_BYTES`); stored documents are PDFs only (upload refuses anything else), so no image path is needed (a failure is a gap, not a crash; `[]` when tesseract is absent). The email body is unchanged. `invoice_text(tenant_id, case_id, *, ocr=False)` forwards the flag. The module docstring's "No OCR (program plan B12)" becomes "OCR only when asked (the worker's deferred scan)".
- `later.classify`: `text or inputs.invoice_text(tenant_id, case_id, ocr=True)`. The inline guard never loads text (it defers the detector), so the request path is untouched; the worker already owns the model call's latency.
- Scope note: an OCR'd page is scanned for the same deterministic patterns; only masked excerpts reach the model (`injection.excerpts`), as today.

## Tests

- `tests/test_trust_agents_retention.py`: with two tenants, rows at 500, 100 and 10 days old plus a 500-day `vendor.create`: the sweep deletes only the 500-day non-create row per tenant; a second run deletes nothing (idempotent); a tenant whose settings read raises is logged and the other tenant is still purged; the sweep runs once per `RETENTION_SCAN_SECONDS` (clock-driven, like `test_the_webhook_sweep_runs_once_per_interval`); `retention_days` below the floor is raised to the floor.
- `tests/test_trust_agents_inputs.py`: `text_of(ocr=False)` on a scan never calls `ocr_page_text` (monkeypatched to fail); `ocr=True` on a document whose layer has fewer than `MIN_TEXT_LAYER_WORDS` calls the bytes path with `max_pages=5` and the OCR text reaches the scan; `ocr=True` on a readable document never calls OCR; tesseract absent → `""` appended and no error; `later.classify` passes `ocr=True` (patch `inputs.invoice_text` and assert the keyword).
- `tests/test_confidence*.py`: existing OCR tests unchanged; one new case: bytes input equals the path input for the same file; `max_pages` stops early.
