## The page `/agents` (h1 "Agents", NAV min approver)

Skeleton as every trust view (`usePoll<Me>("/api/me")` → loading / "approver or above" sentence / error / content; `section.stack`). Write controls render only for `can(me, "admin")`; a viewer never reaches the page (server roles).

1. **Tiles** (`.tiles`, `Tile` with `data-tile`): "Agent blocks" and "Needs review" from `GET /api/trust/agents/blocks/count` (hint "last 24 h"), "Agents" (active count) and "Approved this month" (sum of owners' approved from the tenant ledger).
2. **Agents table** (`panel table-scroll` / `data-table`, `aria-label="Agents"`): name, owner, kind, principal email, status badge (`badge-ok` active, `badge-neutral` revoked), current mandate from the row's `mandate` field (scaffold adds it to the list) — "v2 · until 2027-01-31 · verified" or "none" / "expired" / "unverified" in `badge-warn`. No money per agent row (the ledger is by owner). Below it a **Spend by owner** table from `GET /api/trust/agents/ledger` (no `since`: the default window is this UTC month): owner, agents, approved, paid, blocked, reviews. Money maps per currency render joined, e.g. "INR 1,200.00 · USD 50.00" via `money()`; the "Approved this month" tile uses the same joined text. Row click opens the agent's panel. Filter chips All / Active / Revoked (`btn-chip aria-pressed`). Admin: "Register agent" button → dialog (name, owner email, description, principal one of: "API key" → `{"api_key_id": id}` from a select over `GET /api/integrations/api-keys` (rows carry `id`, `name`, `role`, `revoked_at`; list live keys only); "User" → `{"user_id", "email"}` both required; "External (logs only)" → `principal: null`). Exactly one shape is sent.
3. **Agent panel** (below the table when a row is selected): the mandates list from `GET /api/trust/agents/{id}/mandates` (version, status, validity, scope summary, proposed/approved by, `verified`), and the agent's ledger from `GET /api/trust/agents/{id}/ledger` (approved / paid / blocked / reviews, by vendor and category; last 50 actions with decision badge and explanation). Admin controls: "Propose mandate", "Approve" (on a proposed version; disabled with the hint "A different admin approves" when `proposed_by` is me), "Revoke mandate", "Revoke agent" — each a `.dialog-scrim` dialog with a required reason where the API needs one.
4. **Propose-mandate dialog** (`AgentMandateDialog.tsx`). The contract is `mandates.validate` and the scope section of `docs/API_V2.md` (branch C writes it): `{scope: {actions, currency, counterparties, caps}, valid_from, valid_to, reason?}`. actions as checkboxes over the nine kinds; currency (3 letters); counterparties as a textarea, one vendor name or id per line, sent as a plain string list, empty = `null` (any vendor; the API resolves names to ids, branch C); caps: per action, per period (period select day/month + amount), per vendor, per category (kind → amount rows); valid from / to (`<input type="datetime-local">`, sent as `new Date(value).toISOString()` — the browser's local time converted to UTC). Submits `POST /api/trust/agents/{id}/mandates`; a 400 shows the server's sentence; a 409 ("one pending version") too.
5. **Log import** (admin): a file input + "Import" → `POST /api/trust/agents/actions/import` (multipart); shows `{rows, by_decision, errors}` as a short table. A 409 (engine off) shows the server's sentence and a link to Trust engines.
6. **Empty / dark state:** no agents → `empty-state` "No agents registered." with the register button for admins. The engine mode is not read here; the page is reachable whenever the role allows (Wave 5 surfaces what Wave 4 built dark).

## Banner (U2, B3) — `AppShell.tsx`

`usePoll<AgentBlockCount>(me && can(me, "approver") ? "/api/trust/agents/blocks/count" : null, 60_000)`. A missing or failed response hides the banner. When `blocked + reviews > 0`: `<div className="banner" role="status">⚠ {blocked} agent action(s) blocked and {reviews} need review in the last {window_hours} h · <Link href="/agents">Agents</Link></div>`, placed after the paused banner. Hidden otherwise and for roles below approver. Time-windowed, not acknowledged (program plan risk 5).
