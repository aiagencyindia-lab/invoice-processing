# Non-PO GL auto-coding — plan (spec + contracts)

Goal: every invoice line gets a GL account from tenant rules, a person can
correct it (audited, closed once decided), approvals can route by GL, and
exports carry it. Deterministic rules only; no LLM guessing (ponytail: add an
LLM suggestion source when a design partner's rule coverage is measured low).
Codes all lines, PO or not (PO-line inheritance comes with 3-way match).
Informational: an uncoded line never holds or rejects an invoice.

## Contracts (all tasks code against these exactly)

**Rule row** (`gl_rules` table, dicts from the repo):
`{id: str, vendor_name: str|None, keyword: str|None, gl_account: str,
  enabled: bool, created_by: str, created_at: iso str}`. At least one of
vendor_name/keyword. Limits: gl_account 1–64 (stripped), keyword ≤200,
vendor_name ≤255.

**Coding artifact** `artifacts["gl_coding"]`:
`{"lines": [{"line_number": int, "gl_account": str|None,
  "source": "rule"|"manual"|"none", "rule_id": str|None,
  "coded_by": str|None, "coded_at": iso|None}]}`.

**`gl_coding.code_lines(invoice, lines, rules, previous=None) -> dict`**
(pure, new module `invoice_processing/gl_coding.py`) returns the artifact.
`lines` are `case_projection.lines(artifacts)` dicts (use `line_number`,
`description`). Match: vendor via `po_matching.normalize_vendor` equality
with `invoice["vendor_name"]`; keyword = casefolded substring of description.
Precedence: vendor+keyword > keyword-only > vendor-only; tie → earliest
`created_at`, then input order. Disabled or malformed rules are skipped.
`previous` (the stored artifact): lines with `source == "manual"` are kept
as-is (a re-run never overwrites a person).

**Projection:** `case_projection.lines(artifacts)` sets each line's
`gl_account` from `gl_coding` (by line_number) when that entry has one,
else the transformer's value.

**Approvals:** new rule kind `"gl"`, match `{"gl_prefix": str}` (1–64).
`approval_flow.route()` adds `"_gl_accounts": [non-null gl_account from
artifacts["gl_coding"]]` to the invoice dict it passes to the engine. A gl
rule matches when any account `startswith` the prefix (casefolded). Chain
order: vendor → entity → gl → amount tier. gl rules shape the chain only;
they do not by themselves pull a touchless invoice to a person (same as
vendor/entity rules).

**API (task 5):**
- `GET /api/gl-rules` (clerk+), `POST /api/gl-rules` (admin),
  `PATCH /api/gl-rules/{id}` (admin; gl_account/keyword/vendor_name/enabled),
  `DELETE /api/gl-rules/{id}` (admin). 503 without a DB. Audited
  `gl_rule_created/updated/deleted`.
- `PATCH /api/invoices/{case_id}/lines/{line_number}/gl` body
  `{gl_account: str|None (≤64), remember: bool=false}` (clerk+). 409 when the
  invoice is decided; 404 unknown line. Writes `gl_coding` source "manual",
  coded_by = principal.email; re-projects; re-routes approvals like
  edit_fields does; audits `gl_line_coded` (old → new). `remember` (admin
  only, else 403) also creates a vendor-only rule for this vendor → that gl_account. Returns the artifact.
- `GET /api/cases/...` existing case payloads already include projected
  lines; the case detail must expose `gl_coding`.

**Worker (task 5):** after `_apply_rules`, before projection: if a GL repo
exists, compute `code_lines(...)` with `previous` = stored record's
`gl_coding`, `put_artifact(ctx, "gl_coding", …)`, add to artifacts. Failure
logs and leaves lines uncoded.

**Export (task 4):** Xero `AccountCode` = line gl_account when set, else the
existing map/default. CSV export gets a `gl_account` column per line.
