# Wave 3 API — keys, webhooks, `/v2` façade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (native, chosen by the program). Steps use checkbox (`- [ ]`) syntax.

**Goal:** Per-tenant API keys that authenticate `/v2`, HMAC-signed webhook delivery from the scaffold's outbox, admin routes for both, and a thin `/v2` façade over the existing `/api` handlers.

**Architecture:** `trust/apikeys.py` fills the resolver the scaffold registered (`auth.set_api_key_resolver`). `trust/webhooks/deliver.py` fills `due()`, which the worker sweep calls every 60 s. `api/integration_routes.py` holds the admin routes. `api/v2_routes.py` calls the existing handler functions and declares the same `require_role` dependency as each one, because calling a handler directly skips the handler's own `Depends`.

**Tech Stack:** FastAPI, SQLAlchemy, stdlib `secrets`/`hashlib`/`hmac`, `requests` (already a dependency).

**Spec:** `docs/superpowers/specs/2026-10-21-v2-wave3-api-design.md` (contracts: `…-wave3-scaffold-design.md`; program: `plans/2026-10-21-v2-wave3-program.md` §D).

## Global Constraints

- Touch only: `trust/apikeys.py`, `trust/webhooks/deliver.py`, `api/integration_routes.py`, `api/v2_routes.py`, `tests/test_trust_api*.py`, `tests/test_trust_webhooks*.py`, `docs/API_V2.md`, this plan.
- No new dependencies. Money is Decimal. Log `extra` carries no ids, secrets or bank numbers.
- Every route in `PROBED` (`tests/test_trust_api_routes.py`), probed with a bearer and with a foreign tenant's API key.
- Key plaintext is `ik_{prefix}_{secret}` with `secret = secrets.token_urlsafe(32)` and `key_hash = sha256(secret).hexdigest()`. A key's role is at most `approver`.
- Backoff is `min(2**attempts, 64)` minutes; a row dead-letters at `attempts >= 8`; `timeout=10`; `last_error` is ≤ 500 characters and masked.

## Decisions taken here

- **Prefix lookup under RLS.** `api_keys` has FORCE RLS and production's app role is NOBYPASSRLS, so an engine-level session sees no rows. `resolve` therefore lists the active tenants through an engine-level session (`tenants` has no RLS; `tenant_ids()` already does this) and then looks the prefix up in each tenant's `tenant_session`. The parent session was told. `# ponytail:` ceiling: O(active tenants) queries per key request; a lookup policy like `sso_domains_lookup` would fix that (a scaffold change). A `pg_roles` test proves the lookup works as the app role.
- **Prefix:** 8 hex characters (`secrets.token_hex(4)`), which fits `String(12)`. The format is `ik_` + prefix + `_` + secret; the parser splits on the first `_` after `ik_`. The secret (`token_urlsafe`) may itself contain `_`.
- **Delivery tenants:** only active tenants (the `tenant_ids()` rule); a suspended tenant's events wait.
- **Delivery and audit:** `due(now, *, post=None, limit=50, audit=None, url=None)`. `post` defaults to `requests.post`; `audit` defaults to `service.get_audit()`, resolved only when something dead-letters.
- **Key principals and the integration routes:** a principal whose `user_id` starts with `api-key:` gets a 403 on every `/api/integrations/*` route (a key cannot mint keys or endpoints).
- **Transaction explanation:** lists the transaction's open findings (`store.list(tenant, transaction_node=…)` when the store supports that, otherwise `list_findings` filtered in Python) and calls `trust_explain_routes.get_explanation` for each.
- **Decision mapping:** `accept → accepted`, `reject → rejected`, `needs_vendor_input`. A `detected` finding first goes to `triaged`, with the same reason.

## Review Focus

1. A malformed key (`ik_`, `ik_x`, `ik_abcd1234_`, non-ASCII) → 401, never a 500.
2. A webhook URL `http://…`, a URL with no host, or an unknown event → 422/400. `["*"]` is accepted.
3. A `post` that raises (connection error or timeout) counts as a failed attempt with `last_status=None`, and the sweep moves on to the next row.
4. One tenant's sweep failing does not stop the next tenant's.
5. A revoked key, or a key whose tenant is suspended, → 401 even with the correct secret.
