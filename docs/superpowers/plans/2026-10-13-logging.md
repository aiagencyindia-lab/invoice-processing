# Logging and Error Reporting Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every log line from the API and the worker is one JSON object carrying the request, tenant and document ids; the request id crosses the queue; one line per request and per job; errors reach Sentry when a DSN is set.

**Architecture:** One module, `invoice_processing/observability.py`, owns a context filter (ContextVars → record fields), a JSON formatter, `configure(service)` and the Sentry hook. The API middleware and the worker set the ContextVars and log one summary line each; the queue payload carries `request_id`. Standard-library `logging` throughout; `sentry-sdk` is the only new dependency.

**Tech Stack:** Python 3.12 `logging`/`contextvars`/`json`, FastAPI 0.141, `sentry-sdk>=2.72,<3`, pytest `caplog`, Next.js 16 (one TypeScript change).

**Spec:** `docs/superpowers/specs/2026-10-13-logging-design.md`

## Global Constraints

- Always `./.venv/bin/python`; tests with `-p no:cacheprovider`. `uv sync --frozen` after any lock change.
- Never `git commit -a`; stage explicit paths (`.impeccable/hook.cache.json` is modified and never committed).
- `pyproject.toml` gains exactly `"sentry-sdk>=2.72,<3"`; nothing else is added.
- JSON when `LOG_FORMAT=json`, or when `LOG_FORMAT` is unset and `preflight.is_deployed()`; else text `"%(asctime)s %(levelname)s %(name)s %(message)s"`. Level from `LOG_LEVEL`, default `INFO`.
- Every JSON line has `ts, level, logger, msg, service, env, request_id, tenant_id, document_id`; `exc` when the record has exception info; `extra=` keys pass through.
- Sentry only when `SENTRY_DSN` is set: `send_default_pii=False`, `max_request_body_size="never"`, `traces_sample_rate=0`, `LoggingIntegration(level=INFO, event_level=ERROR)`, `before_send=scrub` drops `Authorization`, `Cookie`, `X-Dev-Principal` request headers. Never print, log or commit a DSN.
- Inbound `X-Request-Id` accepted only if `re.fullmatch(r"[A-Za-z0-9_-]{1,64}", value)`.
- The pipeline's `print` lines are not touched. Emails are not logged.
- Commit trailer: the one the harness names at execution time (currently `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`).
- Ledger: `.superpowers/sdd/2026-10-13-logging/progress.md`; delete at the end.

## Review Focus

1. A log call with `extra={"msg": ..., "exc": ...}` or any key that collides with a standard `LogRecord` attribute: the formatter must not raise or silently drop the line. Pinned in Task 1 (`test_extra_keys_cannot_break_the_line`).
2. A message whose `%` formatting fails (`logger.info("%s %s", one_arg)`): the line must still be written, not lost. Pinned in Task 1 (`test_a_bad_format_string_still_logs`).
3. A request that fails authentication (401) or has no principal: `tenant_id` must be empty on its line, not leaked from the previous request on the same worker thread. Pinned in Task 2 (`test_the_tenant_does_not_leak_to_the_next_request`).
4. A queue message from before this change (no `request_id` key): the worker must fall back to the message id, not crash. Pinned in Task 3 (`test_an_old_message_without_request_id_still_runs`).
5. `configure()` called in a process that already has handlers (uvicorn's, pytest's caplog): it must replace only its own handler and leave caplog's in place, or every test that uses `caplog` after an API import goes blind. Pinned in Task 1 (`test_configure_is_idempotent_and_keeps_other_handlers`).

```python
"""Structured logs and error reporting, configured in one place.

Every line the API or the worker writes is one JSON object carrying the
request id, the tenant and the document, so a line can be joined to the
audit trail (which stores the same request id) and to the Sentry event it
produced. Locally the lines are plain text. Sentry is off unless SENTRY_DSN
is set, so tests and local runs report nothing.

# ponytail: one handler, one formatter; dictConfig when a second sink exists.
"""

from __future__ import annotations

import json
import logging
import os
import sys
from contextvars import ContextVar
from datetime import datetime, timezone

import sentry_sdk
from sentry_sdk.integrations.logging import LoggingIntegration

from .api import preflight

HANDLER_NAME = "ledgerly"
TEXT_FORMAT = "%(asctime)s %(levelname)s %(name)s %(message)s"
_DROP_HEADERS = {"authorization", "cookie", "x-dev-principal"}
# LogRecord's own attributes; anything else on a record came from `extra=`.
_STANDARD = set(vars(logging.LogRecord("", 0, "", 0, "", (), None))) | {
    "message", "asctime"
}

current_tenant_id: ContextVar[str] = ContextVar("tenant_id", default="")
current_document_id: ContextVar[str] = ContextVar("document_id", default="")


def _request_id() -> str:
    from .api import auth  # noqa: PLC0415 -- auth must not import this module

    return auth.current_request_id.get("")


class ContextFilter(logging.Filter):
    """Stamp every record with the ids and the process it came from."""

    def __init__(self, service: str):
        super().__init__()
        self.service = service

    def filter(self, record: logging.LogRecord) -> bool:
        record.request_id = _request_id()
        record.tenant_id = current_tenant_id.get("")
        record.document_id = current_document_id.get("")
        record.service = self.service
        record.env = os.getenv("ENV", "")
        return True


class JsonFormatter(logging.Formatter):
    def format(self, record: logging.LogRecord) -> str:
        try:
            msg = record.getMessage()
        except (TypeError, ValueError):  # a bad %-format must not lose the line
            msg = f"{record.msg} {record.args!r}"
        line = {
            "ts": datetime.fromtimestamp(record.created, timezone.utc).isoformat(),
            "level": record.levelname,
            "logger": record.name,
            "msg": msg,
        }
        for key in ("service", "env", "request_id", "tenant_id", "document_id"):
            line[key] = getattr(record, key, "")
        for key, value in record.__dict__.items():
            if key not in _STANDARD and key not in line:
                line[key] = value
        if record.exc_info and "exc" not in line:
            line["exc"] = self.formatException(record.exc_info)
        return json.dumps(line, default=str)


def _json_wanted() -> bool:
    chosen = os.getenv("LOG_FORMAT", "").lower()
    if chosen:
        return chosen == "json"
    return preflight.is_deployed()


def configure(service: str) -> None:
    """One stdout handler on the root logger; safe to call more than once."""
    root = logging.getLogger()
    for handler in list(root.handlers):
        if handler.name == HANDLER_NAME:
            root.removeHandler(handler)
    handler = logging.StreamHandler(sys.stdout)
    handler.name = HANDLER_NAME
    handler.addFilter(ContextFilter(service))
    handler.setFormatter(
        JsonFormatter() if _json_wanted() else logging.Formatter(TEXT_FORMAT)
    )
    root.addHandler(handler)
    root.setLevel(os.getenv("LOG_LEVEL", "INFO").upper())
    # uvicorn's lines go through the same handler; its access log is replaced
    # by the API's own request line (service._identify_request).
    for name in ("uvicorn", "uvicorn.error"):
        child = logging.getLogger(name)
        child.handlers.clear()
        child.propagate = True
    logging.getLogger("uvicorn.access").disabled = True
    init_sentry(service)


def scrub(event: dict, hint: dict) -> dict:
    """Drop credentials from the event and tag it with the ids."""
    headers = (event.get("request") or {}).get("headers")
    if isinstance(headers, dict):
        event["request"]["headers"] = {
            k: v for k, v in headers.items() if k.lower() not in _DROP_HEADERS
        }
    tags = event.setdefault("tags", {})
    tags.update(
        request_id=_request_id(),
        tenant_id=current_tenant_id.get(""),
        document_id=current_document_id.get(""),
    )
    exc_info = hint.get("exc_info")
    if exc_info and exc_info[0] is not None and exc_info[0].__name__ == "LlmUnavailable":
        event["fingerprint"] = ["llm-unavailable"]
    return event


def init_sentry(service: str) -> bool:
    dsn = os.getenv("SENTRY_DSN", "")
    if not dsn:
        return False
    sentry_sdk.init(
        dsn=dsn,
        environment=os.getenv("ENV", "") or "unknown",
        release=os.getenv("RAILWAY_GIT_COMMIT_SHA") or None,
        send_default_pii=False,
        max_request_body_size="never",
        traces_sample_rate=0,
        integrations=[
            LoggingIntegration(level=logging.INFO, event_level=logging.ERROR)
        ],
        before_send=scrub,
    )
    sentry_sdk.set_tag("service", service)
    return True
```

## Logs and monitoring

The API and the worker write one JSON line per event to standard output
when deployed (`LOG_FORMAT=json`, the default under `ENV=production` or
`staging`). Every line carries `request_id`, `tenant_id` and `document_id`;
the API writes one line per request (method, route, status, duration, ip)
and the worker one per job (outcome, attempt, duration) and per pipeline
step. The request id is also returned to the caller as `X-Request-Id`, shown
to a user on a server error, carried on the queue message to the worker, and
stored on every audit event, so one id joins a user's report, the log line,
the worker's lines and the audit trail.

Logs are kept by the hosting platform for its retention window (Railway:
7 days on Hobby, 30 on Pro). The append-only audit trail in Postgres
(`audit_events`, which the application role can only insert into and read)
is the long-retention security record; an admin exports it as CSV from the
Activity page or `GET /api/audit/export`.

Errors are reported to Sentry when `SENTRY_DSN` is set: unhandled request
errors, jobs that exhaust their retries, and anything logged at ERROR. PII
collection is off, request bodies are never sent, and `Authorization`,
`Cookie` and `X-Dev-Principal` headers are removed before an event leaves
the process. Lines never carry bearer tokens, request bodies, bank account
numbers or email addresses; exception text is logged as raised.
