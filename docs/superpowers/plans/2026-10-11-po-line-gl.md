# PO-line GL Inheritance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An invoice line paired to a purchase-order line takes that PO line's GL account before the vendor/keyword rules are consulted.

**Architecture:** `po_lines` gains a `gl_account` column fed by the ERP PO upload. The worker's existing GL step reads the stored step 2.3 pairing and the PO book, builds a map of invoice line → (PO line, account) with a pure helper, and passes it to the pure `code_lines`, which ranks it between manual entries and rules. Everything downstream (approvals, Xero, sheet, CSV) already reads the account from the same artifact.

**Tech Stack:** Python 3.12, FastAPI, SQLAlchemy 2, Alembic (SQLite locally, Postgres in CI); Next.js 16 / React 19; Playwright. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-11-po-line-gl-design.md`

## Global Constraints

- Always run Python as `./.venv/bin/python` from the repo root. Tests: `./.venv/bin/python -m pytest <file> -q -p no:cacheprovider`. Lint: `./.venv/bin/python -m ruff check . && ./.venv/bin/python -m ruff format .`
- TDD: write the test, see it fail for the expected reason, then implement; record RED and GREEN.
- `gl_account` is at most 64 characters everywhere (`invoice_lines.gl_account`, `gl_rules.gl_account`, now `po_lines.gl_account`). Trimmed; blank is none.
- Precedence per line: manual (from `previous`) → PO account → best rule → uncoded. A PO entry is `{"line_number", "gl_account", "source": "po", "rule_id": None, "po_line_number": int, "coded_by": None, "coded_at": None}`.
- The map is empty (rules apply) unless the 2.3 entry exists and its line count equals the projected line count. Any exception in the GL step logs and keeps rule coding (existing fail-safe).
- Never edit an applied migration. New head revises `a7b3c9d2e4f6`. `RLS_TABLES = []`. Downgrade through `op.batch_alter_table`.
- Every repository query filters `tenant_id` explicitly. No endpoint takes `tenant_id`.
- Comments explain why. Commits: imperative subject saying why, body, trailer `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- Scanned POs (`supporting_docs.to_import_payload`) never set `gl_account`.

## Review Focus

1. **A PO line's account is set but the 2.3 pairing used `paired_by: None` (unpaired) for that invoice line.** Expected: that line falls to rules; other paired lines still inherit. Test in Task 2 (`test_an_unpaired_line_falls_to_rules`).
2. **Transformer line numbers are not 1..n (e.g. 10, 20).** Expected: pairing is by position, so the i-th 2.3 line codes the i-th projected line. Test in Task 2 (`test_pairs_by_position_not_by_number`).
3. **The PO cited by the invoice is not in the book (deleted after processing, or file book).** Expected: `book()` returns None, rules apply, no exception escapes. Test in Task 3 (`test_a_missing_po_falls_back_to_rules`).
4. **A re-import of a PO with the `gl_account` column omitted.** Expected: the account is cleared (the line is replaced whole, like every other field), which the spec states. Test in Task 1 (`test_reimport_without_the_column_clears_the_account`).
5. **A decided invoice whose PO later gets accounts, then its document is retried.** Expected: coding untouched (existing rule). Already pinned by `tests/test_worker.py::TestLinesAreGlCoded` decided-case tests; Task 3 adds the PO variant (`test_a_decided_invoice_is_not_recoded_from_the_po`).

```python
def po_accounts_from_match(
    three_way_lines: list[dict],
    book_lines: list[dict],
    projected_line_numbers: list[int],
) -> dict[int, tuple[int, str]]:
    """Projected line number -> (PO line number, its GL account).

    Step 2.3 numbers invoice lines by their position in the extraction; the
    projection numbers them by the transformer's line_number. The two agree
    by position, and only when the counts do -- the same guard the export
    uses -- so a mismatch yields nothing rather than a wrong account.
    """
    if not three_way_lines or len(three_way_lines) != len(projected_line_numbers):
        return {}
    accounts = {
        ln.get("line_number"): _str(ln.get("gl_account"))
        for ln in book_lines or []
        if isinstance(ln, dict)
    }
    out: dict[int, tuple[int, str]] = {}
    for paired, number in zip(three_way_lines, projected_line_numbers, strict=True):
        po_line = paired.get("po_line_number") if isinstance(paired, dict) else None
        if not isinstance(po_line, int) or isinstance(po_line, bool):
            continue
        account = accounts.get(po_line, "")
        if 0 < len(account) <= 64:
            out[number] = (po_line, account)
    return out
```
