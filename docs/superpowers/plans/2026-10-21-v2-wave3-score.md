# Wave 3 Trust Score Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Per-invoice Trust Score graph node, vendor trust profile, posture dashboard and engine readiness/promotion (FR-25, U2).

**Architecture:** `score.compute` (called by `evaluate()` after the engines) reads findings, the `reality_check` and `document_version` nodes, approvals and the workflow override, runs pure table-driven dimension rules (`dimensions.py`) and upserts a `trust_score` node. Vendor profile, posture and readiness are computed on read (`vendor.py`, `posture.py`, `readiness.py`); routes in `api/trust_score_routes.py` are thin.

**Tech Stack:** Python 3.11, FastAPI, SQLAlchemy, pytest (SQLite; Postgres via `TEST_DATABASE_URL`).

**Spec:** `docs/superpowers/specs/2026-10-21-v2-wave3-score-design.md` (contracts: `2026-10-21-v2-wave3-scaffold-design.md`).

## Global Constraints

- Touch only `invoice_processing/trust/score/**`, `invoice_processing/api/trust_score_routes.py`, `benchmark/history/score.py`, `tests/test_trust_score*.py`, this plan.
- Money is Decimal; leaves as strings (`audit.ledger.money`).
- Read reality/provenance only through `reality_check` attrs `{result,...}` (natural key `reality:{invoice natural_key}`) and `document_version.score`; every dimension degrades to `null` when its source is absent.
- No ids or raw bank numbers in log `extra`; network output names shared key *kinds*, never values.
- Every route has a two-tenant probe; `tests/test_trust_score_routes.py` exports `PROBED`.
- Composite never drives a hold; the gate never reads the score (B4).

## Decisions taken here (builder's calls)

- **Open** = every status but `rejected` (the gate's definition), for values and holds alike.
- **Generic hold rule:** any open hold-type finding in a dimension sets it to 0.0 (agrees with every spec rule; guarantees `dimension_hold_consistency`).
- **Engine-off → null:** a dimension is `null` when none of the engines feeding it (from `types.TABLE`) is on and no finding drives it; this makes `verification_coverage` meaningful.
- `authorization`: approval nodes → rejected 0 / pending 0.5 / all approved with ≥1 `decided_by` 1.0, 0.7 when the workflow has `hold_overridden`; no chain → workflow `decision` (approve 1.0/0.7, reject 0); a history (non-live) invoice with neither → `null`.
- `price` (spec-literal): governing contract (invoice `governed_by` or a contract `governs` the vendor) → leak formula; else open `REAL-PRICE-JUMP` → 0.3; else vendor history → 1.0; else `null`.
- `consistency`: spec rules only; `DUP-*`/`STMT-*` are listed as drivers but do not move the value.
- `computed_at` keeps the prior value when nothing else changed, so a re-run with the same inputs returns the same node id.
- `versions.provenance` / `versions.reality` = the node ids read (graph rows are the versions).
- `pre_payment_share` = prevented ÷ (prevented + recovered) money; `null` when both are 0.
- Readiness `findings`/`failures`/`would_have_held` count findings created since `mode_since`; `precision` from human (actor ≠ `system`) events; `set_mode` requires a non-empty reason.
- Contract-document runs score nothing (ponytail: re-score the vendor's invoices on a contract run if needed).

## Review Focus

1. Invoice with `amount` null or 0 and an open leak → price 0.0, not a ZeroDivisionError (dimensions test).
2. Re-versioned invoice node (sync after an edit) → same score natural key, findings followed; route accepts the old id and resolves the open node (route test).
3. `?as_of` / `?since` malformed → 400, not 500 (route test).
4. Engine never set through `set_engine_mode` (no `since`) → readiness row with `since: null`, `days_in_mode: 0`, no crash (readiness test).
5. Batch (tenant-wide) run → every invoice node gets a score (compute test + benchmark gate).
